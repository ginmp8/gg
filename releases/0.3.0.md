# GG Analytics 0.3.0 — proposed release

**Status (November 6, 2026):** Release documentation draft. Version 0.3.0 has **not** been tagged, packaged, or published.
**Source snapshot:** [`acf442aa`](https://github.com/ginmp8/gg/commit/acf442aa0ce32e70e38d4e22e74ba0929f51fae2) (the shared `main`/`development` baseline before this documentation change).
**Version metadata:** Root/workspace manifests, lockfile, Tauri configuration, and Rust package metadata still identify **0.2.0**. Align all of them before building or tagging v0.3.0.
**Release date and artifacts:** Not yet determined. No installer or release asset is claimed here.

## Release scope and provenance

GG Analytics is a local-first, read-only engineering analytics application for projects containing one or more Git repositories. The earlier [0.2.0 candidate](0.2.0.md) was never published as a GitHub Release; its code was subsequently promoted to `main` through [PR #3](https://github.com/ginmp8/gg/pull/3). As a result, the highlights below describe the **consolidated candidate product**, not a claimed feature delta from a publicly released v0.2.0.

## Product highlights

### Annual contribution and evidence

- Analyze all commits reachable from each configured integration branch, without a 500-commit history cutoff. Cache versioned per-SHA and per-file diff measurements in local SQLite for incremental re-indexing.
- Inspect integrated and substantive commits, active days/months, source/test/documentation changes, rename-aware churn, whitespace-adjusted churn, and monthly trends.
- Use **ICE-Git/1** (effective contribution evidence) and **GG-Throughput/1** (technical throughput proxy), with transparent cohort-relative components and source evidence. These experimental 0–100 indicators **do not measure human productivity, engineering quality, or business value**.
- Export annual evidence as local CSV or JSON. Optionally enrich it with explicitly fetched GitHub PR/review snapshots and manually linked identities.

### Comparison and project organization

- Compare any number of contributors, retaining project/repository/year selections when switching tabs or restarting the app.
- Select all contributors matching the current tag/search filters, inspect the complete annual metric inventory, compare monthly values, and export selected comparisons as JSON.
- Organize contributors, repositories, branches, and pull requests using custom tags and optional groups.
- Explore consolidated, paginated branch/PR inventories across repositories, branch comparisons, file types, hotspots, and reusable folder-filtered branch views.
- Use a January 1–today default date window, with local persistence of explicit filter choices.

### Local tools, desktop, and privacy

- Query cached SQLite analytics through the read-only JSON CLI, including dataset discovery, annual scores, and paginated raw evidence tables. A Node.js source checkout is required; desktop installers do not bundle the CLI.
- Optionally build the Tauri 2 desktop distribution for Windows x64, Linux x64, and macOS arm64, with a bundled Node.js API sidecar.
- Keep analysis data in the GG-owned local directory, with protection for existing `.gita` installations and preferences during the brand transition.
- Clone/fetch registered Git remotes **only** when explicitly refreshed; optional GitHub CLI metadata uses separate read-only controls. Offline switches can deny network activity.
- Restrict the local API to loopback by default. The browser/server mode has no user authentication and must not be exposed directly to untrusted networks.

## Requirements and upgrade notes

- **Source/web:** Node.js 24+, npm, and Git. Install dependencies with `npm ci`; start with `npm run dev`. GitHub CLI (`gh`) is optional for GitHub metadata and requires separate authentication.
- **Data safety:** Back up the application's local `.gg/` or legacy `.gita/` data before upgrades. Annual analytics and tags use additive SQLite data. Existing databases are detected instead of being implicitly deleted or moved.
- **Desktop migration:** The GG desktop identifier differs from the former brand; operating systems may treat it as a separate app. Verify local data and settings before uninstalling any previous installation.
- **Network/security:** A manual refresh may contact the configured Git remote. `GG_OFFLINE=1`, `GG_ALLOW_REMOTE_GIT=0`, and `GG_ALLOW_GITHUB_METADATA=0` provide the documented restrictions; these are application controls, not an OS firewall.
- **Metrics interpretation:** Missing collaboration data is not zero; the experimental scores must not be used alone for personnel decisions.

## Known limitations

- The 0.3.0 package/desktop metadata and build identities have **not** yet been synchronized; the documentation is not itself a releasable binary.
- The browser-based API has no login/authentication; avoid public or shared exposure without a separate security boundary.
- Historical security notes report unresolved advisories in the development-inclusive dependency set. Re-run the full and production-only audits against the final lockfile; old findings are not a current scan.
- Platform-specific installer validation, signing/notarization, and visual smoke tests require the final candidate and representative operating systems.

## Verification and publication gates

**Not executed as part of this documentation update:** final-candidate installation, lint, typecheck, unit/integration tests, web build, dependency audit, GUI checks, or native installer smoke tests. GitHub Actions must be reviewed after the PR is opened.

Before publishing v0.3.0:

1. Synchronize version identifiers in the root/workspace manifests, npm lockfile, Tauri configuration, and Rust package metadata. Re-check any tag-to-version workflow guard.
2. Run `npm ci`, `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`, `npm run desktop:check`, and `npm audit --omit=dev --audit-level=high` on the final release commit. Review the development-inclusive audit separately.
3. Verify annual indexing, comparison selection persistence, filtered select-all, local CLI JSON output, project deletion safety, network consent/offline behavior, and screenshots without a Next.js dev overlay.
4. Build and manually smoke-test Windows, Linux, and macOS packages; decide on signing/notarization, inspect artifacts, and verify local-data upgrade/rollback behavior.
5. After approval, create a tag for the exact validated commit and invoke the manual, gated GitHub Release workflow. Do not infer publication from a merged PR.
