# Gita 0.2.0 — development release candidate

**Status:** version metadata and features prepared on development.
Not merged into main, tagged or published as a GitHub Release.

## Engineering analytics
- Full integration-branch history, analyzed incrementally by SHA using local SQLite,
  rename-aware and whitespace-adjusted diffs and auditable file/commit evidence.
- ICE-Git/1 effective contribution score and Gita-Throughput/1 technical
  productivity proxy (both experimental, cohort-relative, 0–100).
- Side-by-side Compare tab with two to four user-selected developers,
  custom tag candidate filters and aligned metric comparisons.
- Local annual CSV/JSON exports and optional GitHub collaboration enrichment.

## Projects, views and organization
- Combined, paginated Branches and Pull requests tables in All repositories
  mode, with source Repository column.
- Arbitrary custom tags/groups assigned to contributors, repositories,
  branches and pull requests; no predefined categories.
- Dedicated Settings tab for workspace operations, appearance, saved
  branch views/folder filters and tag management.
- Existing analytics, GitHub discovery, dark mode and safe local deletion
  features remain available.

## Runtime and security
- Read-only GitHub metadata enabled by default with authenticated gh;
  GITA_OFFLINE=1 or GITA_ALLOW_GITHUB_METADATA=0 can disable it.
- Git clone/fetch still requires explicit refresh. Gita never writes to
  source repositories or remotes.
- Optional Tauri 2 desktop bundling remains opt-in.

## Upgrade
- npm workspace packages, lockfile, Tauri configuration and Rust package
  metadata are aligned to 0.2.0.
- Existing analytics data is preserved. The additive SQLite migration adds
  project_tags and project_tag_assignments only; back up local data before upgrading.
- No new package dependencies are required for the introduced features.

## Gates before publication
- Verify lint, typecheck, tests, Next.js build, production dependency audit
  and native desktop packaging for the final commit.
- Validate browser interaction, Windows/macOS/Linux installers and optional
  GitHub CLI authentication in representative environments.
- Scores do not prove code quality, business impact or human productivity.
- The v0.2.0 tag is intentionally deferred until the merge into main is approved.
